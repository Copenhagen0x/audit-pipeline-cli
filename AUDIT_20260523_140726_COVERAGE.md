# Audit 20260523-140726 — Patch Coverage Manifest

This file tracks the 17 fix-branches produced from audit cycle
`20260523-140726` (synthesis output: 728 findings; 62 validated
CRITICALs; 185 validated HIGHs in bucket FIX-THIS-WEEK).

Each patch lives on its own `fix/audit-NNN-<class>` branch. The
iterate-until-clean process required TWO independent review gates to
produce a clean verdict (`Nothing to find.` or `Verdict: ship` —
both accepted by `mark_patch_clean.py`):
  * `code-reviewer` (correctness + cross-file impact) — used on every
    patch P1-P17
  * Adversarial second gate — same role under two different agent
    names across the chain. Per-patch agent attribution from the
    canonical clean-marker files:
      - `paranoid-goober`: P1, P2, P3, P4, P5, P6, P15, P16
      - `devils-advocate`: P7, P8, P9, P10, P11, P12, P13, P14, P17

The `threat-modeler` agent contributed analysis on P15-P17 and on
the synthesis stage, but the canonical clean-marker files in
`~/.claude/state/audit-20260523-140726/` certify only the two gates
above. The clean-marker files are operator-local; not committed to
this repo — they certify gate passage on the original machine but
are NOT machine-verifiable from a fresh clone. Canonical
verification is each branch's commit log + a passing
`pytest tests/` run.

**P17 specific note**: this manifest is itself patch P17. The
clean-marker `patch-017-clean.txt` was written for the R0 version of
this file. The operator MUST re-write the marker via
`mark_patch_clean.py mark --patch-id 017` immediately after the
final R-N gate passes on the eventually-shipped text; the commit
that lands the rewritten manifest is the canonical evidence that
R1+ changes were re-gated. Until then the marker certifies R0 only.

**No automatic merge.** Merging the 17 branches to `main` requires
explicit operator sign-off. The standing operator instruction is to
keep them on separate branches until the full chain is reviewed in
aggregate.
